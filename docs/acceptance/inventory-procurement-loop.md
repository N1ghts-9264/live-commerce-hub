# 库存管理与采购联动专项说明

## 1. 设计边界

库存管理不再只等同于“当前库存低于安全库存”。本项目将库存管理定义为供应链风险控制台，负责把库存、销售、直播排期、主播影响力、供应商交期、在途采购和人工采购决策整合起来。

边界内：

- 根据当前库存、安全库存、供应商交期和销售速度计算动态补货点。
- 根据未来直播场次和主播影响力提前识别直播备货风险。
- 对高潜力商品或新品试播商品提高备货敏感度。
- 在库存管理页直接生成采购单，默认采用系统建议量，但允许人工修改。
- 在采购管理页创建之前不存在的新品采购，并把新品放入待评估候选池。

边界外：

- 不做复杂供应链优化模型或多仓路径规划。
- 不替代采购人员审批，只生成待审核采购单。
- 不新增复杂财务结算流程。

## 2. 补货口径

系统使用动态补货点，而不是单一安全库存：

`动态补货点 = 安全库存 + 供应商交期内需求 + 未来直播备货需求 + 新品试播预留 + 爆款缓冲`

`建议采购量 = max(动态补货点 + 安全库存/预警阈值 - 当前库存 - 在途采购, 0)`

主要输入：

- `Inventory.current_stock`：当前仓库库存。
- `Inventory.safety_stock`：安全库存。
- `SKU.sales_volume`：历史销量，用于估算 30 天需求。
- `Supplier.delivery_cycle`：供应商交付周期。
- `PurchaseOrder`：待审核、已审核、已发货采购单作为在途采购。
- `LiveSession`、`Anchor`：未来排期和主播等级/粉丝量形成直播备货需求。
- `Product.product_status`：`待评估` 新品需要保留试播库存。
- `ProductPerformance`：商品转化、互动和 GMV 用于估计潜力。

## 3. 业务流程

1. 仓储或采购人员进入“库存管理”。
2. 系统展示高风险 SKU、涉及直播备货 SKU、在途采购量、本页建议采购量。
3. 每个库存行显示预测销量、直播需求、在途采购、建议采购量和风险原因。
4. 用户点击“一键采购”，系统带出 SKU、供应商、建议采购量、采购价和预计到货日期。
5. 用户可修改采购数量、采购价和预计到货日期。
6. 保存后生成 `PurchaseOrder.purchase_status = 待审核` 的采购单。
7. 采购管理页负责后续状态流转：待审核、已审核、已发货、已入库、已完成。
8. 当采购单状态推进到已入库，系统更新库存数量。

## 4. 新品采购

“新增新品采购”用于采购当前系统不存在的新品。

保存时系统在一个事务中创建：

- `Product`：状态为 `待评估`，进入新品冷启动候选池。
- `SKU`：默认 SKU。
- `Inventory`：默认主仓库存记录。
- `PurchaseOrder`：待审核采购单。

该流程让采购、库存、选品冷启动形成闭环：新品先通过采购进入候选池，再在选品分析中做冷启动评估，后续通过试播数据决定是否继续采购或放量。

## 5. 验收演示路径

- 库存联动采购：登录 -> 库存管理 -> 查看动态风险 -> 点击一键采购 -> 修改建议采购量 -> 生成采购单。
- 新品采购：登录 -> 采购管理 -> 新增新品采购 -> 填写新品信息 -> 保存 -> 到选品分析中查看待评估新品。
- 采购入库：采购管理 -> 打开采购单详情 -> 推进到已入库 -> 回到库存管理查看库存变化。
