# 新品冷启动专项分析与设计

## 1. 问题边界

本项目中的“新品冷启动”不是全网爆品发现系统，而是直播电商企业内部运营后台中的候选商品评估流程。

边界外：

- 自动扫描全网商品、爬取竞品平台、预测全市场爆款。
- 直接替代采购、运营或主播的业务判断。
- 面向消费者的个性化推荐前台。

边界内：

- 对已经进入候选池或商品库的新品做初始评估。
- 在缺少自身成交、互动、售后和直播表现时，使用相似商品、品类趋势、供应链和库存信息补足先验判断。
- 给新品小流量试播机会，并在首场或前三场直播后根据真实数据复盘。
- 为运营提供主播、时段和话术方向建议，支撑试播执行。

## 2. 业务定义

新品冷启动是指：商品已经由供应商、平台商品池、自有商品池或品牌活动池进入系统，但在本系统中缺少历史销售、互动、直播转化和售后数据，常规“按历史表现排序”的选品模型无法直接评价。系统需要先给出可解释的初评分，再通过有限流量试播收集真实反馈，最后判断继续投放、观察或下架。

本项目将新品处理分成五步：

1. 候选进入：供应商或运营录入商品、SKU、库存、成本、售价、供货周期和卖点。
2. 基础过滤：检查价格、毛利、库存、供应商评分和履约周期。
3. 冷启动初评：匹配相似商品、读取品类趋势、计算供应链与库存准备度。
4. 小流量试播：安排 1-3 场低风险直播，给予探索加权。
5. 早期复盘：根据点击率、互动热度、转化率、GMV、退款率和负面反馈决定加码、继续观察或暂缓。

## 3. 数据流

外部输入：

- 供应商：候选商品、成本价、建议售价、库存、供货周期。
- 直播平台：直播场次、点击、互动、弹幕、加购、成交。
- 支付/订单系统：订单金额、数量、支付状态。
- 售后/物流系统：退款、退货、履约异常。

系统存储：

- `Product`：商品基础信息和 `product_status`。
- `SKU`、`Inventory`：规格和库存。
- `Supplier`：供应商评分和供货周期。
- `ProductPerformance`：商品在直播中的点击、转化、GMV、互动和退款表现。
- `LiveSession`：试播场次及其时间窗口。
- `PurchaseSuggestion`：后续采购建议。

处理输出：

- `estimatedScore`：新品初始潜力分。
- `scoreComponents`：相似商品、品类趋势、供应履约、库存保障、毛利空间、试播信号。
- `explorationBoost`：新品探索加权，随上架时间和试播次数衰减。
- `confidence`：low / medium / high。
- `decision.action`：加码试播、建议试播、继续观察、暂缓投放。
- `trialStrategy`：小流量试播策略和复盘指标。
- `executionSuggestions`：主播、时段和话术方向。

## 4. 评分规则

冷启动评分不直接套用老品历史销量排名，而是使用多源先验：

| 维度 | 含义 | 项目实现 |
| --- | --- | --- |
| 相似商品 | 同品类、相近价格、相近毛利、同品牌商品的历史表现 | `similarProducts` 和 `performanceScore` |
| 品类趋势 | 同品类近期转化、点击、互动、GMV 和退款表现 | `categoryTrend` |
| 供应履约 | 供应商评分、供货周期 | `supplierReadiness` |
| 库存保障 | SKU 库存和仓库库存 | `inventoryReadiness` |
| 毛利空间 | 毛利率是否支持直播间优惠和投流 | `grossMargin` |
| 试播信号 | 已有少量直播表现时，用真实数据替代估计 | `trialSignal` |

探索加权用于解决“新品没有机会就没有数据”的矛盾。新品在早期获得临时加权，但该加权会随上架时间和试播次数衰减，避免长期挤占老品排序。

## 5. 决策口径

系统输出不是绝对预测，而是运营决策建议：

- `加码试播`：初评分和探索加权均较高，可安排更靠前的直播资源。
- `建议试播`：达到小流量验证门槛，建议安排 1-3 场试播。
- `继续观察`：证据不足，需要补充卖点、库存、供应支持或首场反馈。
- `暂缓投放`：基础条件不足，不建议直接占用直播资源。

置信度随试播数据增加：

- `low`：无试播或少量数据，仅能作为初评。
- `medium`：完成约 3 场试播，具备早期复盘基础。
- `high`：完成约 6 场以上或数据充分，可进入常规选品评分。

## 6. 验收演示路径

1. 运行 `npm run seed:acceptance` 准备候选商品、库存、供应商、场次和表现数据。
2. 登录系统，进入“选品分析”。
3. 点击一个商品行，确认工具栏出现已选商品。
4. 点击“新品冷启动评估”。
5. 查看预估分、置信度、探索加权、建议动作、评分构成、试播策略、执行建议和相似商品。
6. 说明系统边界：不是全网找爆品，而是对候选池新品做小流量试播决策。

## 7. 理论与实践依据

- 推荐系统冷启动问题通常需要内容属性、相似物品和混合推荐补足交互数据不足的问题。参考：Schein 等，Methods and Metrics for Cold-Start Recommendations，SIGIR 2002。
- 新品试播中的“探索加权”对应探索-利用思想：既不能只利用老品历史表现，也不能无限给新品资源。参考：Li 等，A Contextual-Bandit Approach to Personalized News Article Recommendation，WWW 2010。
- 工业预测实践中，无历史商品通常依赖商品元数据和相似商品历史序列作为冷启动先验，例如 Amazon Forecast 的 cold-start forecast 实践。
