# 平台数据接入与新品选品流程说明

## 1. 系统边界

本系统是直播电商企业内部运营后台，不是面向消费者的购物前台。消费者、供应商、直播平台、支付平台和物流平台是外部实体或数据来源。

- 消费者：产生订单、互动、浏览、停留和售后数据。
- 供应商：提供候选商品、成本价、供货周期、库存和履约能力。
- 直播平台：输入直播场次、在线人数、弹幕、点赞、加购、成交等实时数据。
- 支付平台：输入支付状态和订单金额。
- 物流平台：输入发货、签收、异常和退货状态。
- 内部操作用户：管理层、运营、采购、仓储、主播、系统管理员。

## 2. 平台数据如何进入系统

验收数据中的 `InterfaceLog` 用于模拟平台接口接入过程。每条接口日志记录平台名称、接口名称、请求时间、响应状态、数据量和错误信息。

核心数据流如下：

1. 直播平台接口输入 `直播实时指标` 和 `互动日志`，落入 `LiveSession`、`InteractionLog`、`UserBehaviorStat`。
2. 订单/支付接口输入 `订单明细` 和 `支付状态`，落入 `[Order]`。
3. 物流/售后接口输入 `退货退款和异常原因`，落入 `AfterSale`。
4. 供应商接口或采购录入输入 `候选商品清单`、`供货周期` 和 `采购价格`，落入 `Supplier`、`Product`、`SKU`、`PurchaseOrder`。
5. 业务层聚合商品表现，形成 `ProductPerformance`、`PurchaseSuggestion` 和 `OperationReport`。

## 3. 候选商品池

候选商品池由 `Product`、`SKU`、`Supplier` 和 `Inventory` 共同表达：

- `Product.product_status = 在售`：可参与常规排名。
- `Product.product_status = 待评估`：可作为新品或候选商品进入冷启动评估。
- `Supplier.supplier_score`、`delivery_cycle`：参与供应稳定性判断。
- `SKU.stock_quantity` 与 `Inventory.current_stock`：参与可播库存判断。

验收种子写入 144 个商品、432 个 SKU、24 个供应商和 864 条库存记录，足够支撑筛选、排序和采购建议演示。

## 4. 新品冷启动流程

新品没有足够历史成交数据时，系统不能简单排除，而应进行小流量试播评估。

流程如下：

1. 运营人员在选品分析页点击候选商品。
2. 系统读取商品品类、价格、品牌、毛利率和供应商信息。
3. 系统寻找同品类、相近价格、相同或相近品牌的相似商品。
4. 系统读取该品类近期直播表现，形成品类趋势摘要。
5. 有 LLM 密钥时生成智能评估；无密钥时使用本地规则返回潜力等级、预估转化、目标人群、讲解角度和风险提示。
6. 系统给出 `estimatedScore`、`confidence` 和 `explorationBoost`，建议先进入小流量直播试播。

## 5. 实时数据时间维度

直播实时数据不是单点汇总，而是带时间戳的连续记录：

- `InteractionLog.interaction_time`：每条弹幕、点赞、加购等互动发生时间。
- `UserBehaviorStat.statistical_time`：按时间片统计点击率、转化率、平均停留、跳出率和活跃用户数。
- `LiveSession.start_time/end_time`：直播场次的业务时间窗口。
- `ProductPerformance` 通过 `live_id` 关联到场次时间，用于比较最近周期和上一周期表现。

趋势评分已改为确定性 recent-vs-previous 计算，同一数据下连续刷新不会出现随机变化。

## 6. 现场说明口径

验收时可这样说明：

本系统的核心不是把消费者当后台用户，而是把消费者行为作为外部数据输入。平台接口、供应商和物流支付系统把业务数据送入后台；后台通过权限、流程和算法把数据转化为选品、采购、直播执行、售后和报表决策。这对应信息系统分析与设计课程中的外部实体、数据流、处理过程、数据存储和管理输出。
