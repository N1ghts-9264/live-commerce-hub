# 现场验收测试台

## 测试台 A：管理层综合看板

- 账号：`EMP001` / `123456`
- 角色：管理层
- 目标：证明系统能支撑管理决策。
- 操作路径：登录 -> 驾驶舱 -> 运营报告 -> 主播绩效 -> 接口日志。
- 核验数据：GMV、订单数、直播场次、主播绩效、平台接口成功/失败日志。
- 预期结果：管理层可看到跨模块汇总，不需要进入每个业务表手工统计。
- 课程对应：管理输出、数据流终点、报表与 KPI。

## 测试台 B：运营人员直播与选品

- 账号：`EMP002` / `123456`
- 角色：运营人员
- 目标：证明直播运营能从选品分析进入直播执行。
- 操作路径：登录 -> 选品分析 -> 点击商品 -> 新品冷启动评估 -> 关联推荐 -> 直播场次 -> 直播监控。
- 核验数据：商品评分、趋势标签、冷启动分、相似商品、直播互动。
- 预期结果：运营人员能解释为什么选择某商品，并能把选择结果用于直播场次。
- 课程对应：业务处理过程、算法规则、直播实时数据时间维度。

## 测试台 C：采购人员供应链闭环

- 账号：`EMP003` / `123456`
- 角色：采购人员
- 目标：证明选品结果能反馈到采购流程。
- 操作路径：登录 -> 选品分析 -> 采购建议 -> 采购单 -> 供应商。
- 核验数据：预测销量、建议采购量、库存风险、供应商评分、预计到货时间。
- 预期结果：采购人员能按建议生成或审核采购单，并查看供应商履约信息。
- 课程对应：候选商品池、供应商外部实体、CRUD 矩阵。

## 测试台 D：仓储与售后处理

- 账号：`EMP004` / `123456`
- 角色：仓储人员
- 目标：证明库存和售后不是孤立表单，而是订单后的业务闭环。
- 操作路径：登录 -> 库存管理 -> 库存预警 -> 售后管理 -> 更新售后状态。
- 核验数据：SKU 库存、预警阈值、订单关联售后、退款金额、处理状态。
- 预期结果：仓储人员能定位风险库存，运营/售后人员能完成售后状态流转。
- 课程对应：数据存储、异常流程、状态转换。

## 测试台 E：主播执行辅助

- 账号：`EMP005` / `123456`
- 角色：主播
- 目标：证明主播不是管理后台的泛用户，而是具体业务参与者。
- 操作路径：登录 -> 脚本管理 -> 主播绩效 -> 直播监控。
- 核验数据：商品讲解脚本、转化率、互动率、观看时长、绩效得分。
- 预期结果：主播能查看与自身直播执行相关的信息。
- 课程对应：Use Case 参与者、岗位职责、输入输出边界。
